## 已知歷史證據邊界

- 2026-11-05 匯入訊號的 Created_At 為開發者保存的來源敘述；儲存庫首次記錄晚於其 11/06 模擬成交。這不是偽造的證據，但目前缺少可獨立核實的進場前發布證據。原 bytes 與後續可稽核訊號分開處理。
- 2026-11-06 已發布訊號缺 Price_Sha256、Sentiment_Sha256、Fetched_At。不得回寫成原先已有完整證據；以新增側錄連結可用資料及無法確認部分。
- `experiments/results/v2/v28/` 的 `predictions.csv`、`schedule_predictions.csv`、`schedule_cost.csv`、`fixed_predictions.csv` 未隨 Git／ZIP 完整提供；原研究價格目前以雜湊相同的 reproducible fixture 解析。中間預測補齊之前，不宣稱可獨立重算全部 V2 歷史比較。
- ZIP 交付版本與目前整合程式版本不同。ZIP checksum 相符只證明檔案相同，不代表來源完整，也不代表與當前程式版本一致。
- 舊 444 固定持股 ROI 不證明 LSTM 擇時獲利；舊 555 同日收盤成交的理想化結果，不直接等於修正後的可交易績效。
- 尚未成熟的五日標籤保持缺值，不能用預測代替實現值。60 個成熟訊號日是首次人工檢視門檻，不能自動宣稱統計顯著或推薦替換正式模型。

## 新版本驗收時應附的證據

每次交付應附實際 commit、測試指令與結果，以及凍結權重、原始訊號、模型卡的修改前後雜湊。主要反例需涵蓋未來特徵注入、未來 validation 注入、風險狀態跨日變動、假日新聞、模型依賴遭改及未排程交易。

配對研究應附 protocol、來源雜湊、各組逐日 NAV、成交與成本明細，標明 exploratory／prospective 及新聞品質。新結果生成後，舊報告保留原標籤與原數字，新報告清楚說明修正了哪些假設；不能只用新程式覆寫舊檔而不留下變更依據。

操作與研究判讀見 [研究協議 v2](research_protocol_v2.md)。本表的歷史限制，不能靠單元測試或重新抓取當前來源自動解除。
