# Streamlit 完整專案展示

此頁是整份專題的研究入口，展示444、555、555 V2、V2.11、修訂／延伸研究及V3的保存結果。網站不訓練、抓行情、改選模型或覆寫每日系統。入口仍為 [`dashboard/app.py`](../dashboard/app.py)，根目錄的 `streamlit_app.py` 也可啟動相同頁面。

## 啟動

建議獨立使用 Python 3.12 虛擬環境，無須安裝每日訓練的 TensorFlow／PyTorch 套件或提供 FinMind 金鑰：

```bash
python3.12 -m venv .venv-dashboard
. .venv-dashboard/bin/activate
python -m pip install -r dashboard/requirements.txt
python -m streamlit run dashboard/app.py
```

在 repository 根目錄執行，開啟終端顯示的網址，預設為 `http://localhost:8501`。Windows 可用 `.venv-dashboard\Scripts\Activate.ps1` 啟用環境。

若使用 Streamlit Community Cloud，選擇本 repository、`main` 分支與 `dashboard/app.py` 入口，**Advanced settings明確選Python 3.12**；套件清單位於同目錄 `dashboard/requirements.txt`。Python3.14會讓本版NumPy嘗試原始碼編譯，不能沿用該預設。GitHub更新後由Streamlit同步部署，必要時在Manage app選Reboot app；網站內「重新讀取保存報告」只讀目前checkout，不會Git pull。部署應保留完整checkout的報告與展示快照；不需上傳私人行情快取或金鑰。

## 每日自動更新

不需要每天手動執行或Reboot：

1. GitHub Actions排定台北週一至週五17:37、21:37執行四系統，每日09:17另作重試；實際開始時間可能延遲。
2. 流程取得來源、執行444／555、保存合法的凍結模型預測／帳本進度、追加日誌與新聞展示標題，再自動commit至`main`。來源未齊會保留實際等待／部分結果，不補造當日成功。
3. Community Cloud連接`main`，自動同步新commit。網站已加入每300秒觸發的Streamlit fragment，對整頁重新執行，讓**已開啟的頁面**讀到同步後的報告。頁面閒置關閉不影響GitHub每日流程，之後開啟可讀部署的最新資料。

側欄顯示「本頁讀取」時間；總覽另外顯示**資料截止交易日、真正執行日及模型生成時間**。前者不是新的模型執行或資料取得證據。讀取計時器只重新載入本機部署報告，不訓練、不抓行情、不修改研究檔案，也不會自行Git pull。本機執行的使用者仍須自行更新checkout；Cloud同步則由平台管理。

## 資料來源與保護

- 績效、逐折驗證、選擇紀錄及設定直接來自 [`reports/research_v3_3/2026-11-17/`](../reports/research_v3_3/2026-11-17/) 與 [`reports/research_v3/2026-11-10/`](../reports/research_v3/2026-11-10/)。
- 曲線快照只含日期、組別、衍生投資組合淨值指數與回撤，位於 [`dashboard/assets/`](../dashboard/assets/)。不含FinMind原始／完整標準化行情、逐股報價、新聞全文或私人來源路徑。
- 淨值是已保存帳本NAV除以共同初始資金再乘100，保留進場成本；回撤以初始100計入高水位。相對財富是策略淨值除以0050淨值減一，與報酬百分點差不同。
- `manifest.json` 記錄快照、公開報告與私人研究來源的雜湊鏈。載入時檢查來源雜湊、四組完整共同日期、有限正淨值、ROI及最大回撤一致性；缺檔或不一致會停止顯示績效，不用範例值代替。
- 每日運作讀取checkout的 `reports/latest/four_systems.json`，分開顯示資料日與真正執行日。頁面按鈕僅重新讀取本機報告；最新每日狀態需更新checkout或重新部署。
- 444／555績效讀取 `reports/daily/<資料日>/paired/`，核對保存manifest、共同日期、完整帳本與期末ROI；原生Notebook績效另列為診斷，不與配對ROI混排。V2.11核對已保存帳本前綴雜湊。
- 日誌直接讀取 `reports/daily/`、`reports/journals/` 與 `reports/attempts/`，保留原文；缺日誌、缺預測與缺來源均明示，不以零值或昨日資料代替。
- 新聞合併兩份已公開評分快取，按完整評分列hash去重，保留股別及版本差異；取得證據只與相同評分列配對。標題來自新增 `data/news_display_metadata.jsonl`，**現在取得的標題不證明原評分時的內容或可用性**。舊來源沒有網頁截圖，網站不補造截圖。

原始報告、凍結模型與訊號未被展示頁修改。離線查看不需要外部資料服務；點擊GitHub／新聞原文連結才需要網路。每日排程保持原時段，新增一個可失敗的展示標題步驟，不改研究結果或退出碼；標題後續由同一每日commit同步至網站。

## 新聞標題保存

已保存新聞共有40個文章ID、44筆股別評分列；本次另於2026-11-17取得40篇展示標題。標題只保存現在觀測的標題、來源URL、實際取得時間與hash，不包含全文或私人行情。公開快取中23列有取得／評分紀錄，其餘歷史列仍缺證據；有紀錄也須另與當時決策時點比較，不能一律稱為PIT通過。

```bash
# 唯讀檢查，不連線、不寫入
python -m scripts.capture_news_display
# 明確擷取已保存評分ID尚缺的標題；不改原分數／provenance
python -m scripts.capture_news_display --capture --limit 50
```

擷取失敗會保留缺標題狀態，不寫假文字；成功記錄只追加。每日流程在模型作業後、保存狀態前執行此步，失敗不改模型狀態。狀態保存器只允許窄格式的標題metadata，拒絕舊列改寫及全文欄位。

## 驗證與展示快照重建

```bash

python -m pytest -q tests/test_dashboard*.py tests/test_news_display*.py tests/test_research_charts.py tests/test_v2_presentation.py tests/test_v2_diagnostics.py

```

最後一個命令預設唯讀，只檢查已保留展示資料。測試涵蓋曲線與原績效一致、雜湊／缺檔阻擋、版本與圖表互動，以及操作前後研究檔案不變。獨立的 `dashboard.yml` CI安裝輕量展示依賴執行這些測試；沒有Streamlit的每日環境可略過UI測試。

2026-11-17初次完整專案展示擴充驗證：全套448項通過；展示與標題保存測試51項，另連同既有狀態保存測試共60項通過。六個導覽區、日誌搜尋、逐日模型切換、新聞時點與唯讀操作均檢查，瀏覽器無頁面錯誤、手機無頁面水平溢出。凍結權重、模型卡與完整bundle雜湊均維持原值。測試不代表新聞模型已證明勝出。

只有持有合法保留的兩版私人研究目錄，且雜湊與原公開來源一致時，才能顯式匯出到**新的空目錄**：

```bash
python -m scripts.export_dashboard_data --write \
  --v33-run /private/retained-v33-run \
  --v32-run /private/retained-v32-run \
  --output-dir /tmp/new-dashboard-snapshot
```

這些是自行替換的私人目錄範例。匯出器拒絕覆寫既有快照，不更動舊來源manifest，也不複製受限制的行情快取。新增研究版本需要另行審核與登記，不能為了畫出勝出曲線而刷新來源。
