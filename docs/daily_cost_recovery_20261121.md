## 原因與資料影響

凍結帳本的 `rebalance()` 正確收取買進手續費、賣出手續費與賣稅，`Cost` 包含三項；但原 `live_fills.csv` 只另存 `Buy_Fee`、`Sell_Tax`。展示程式誤以為這兩欄必須等於 `Cost`。11/20 首次出現含賣出的再平衡，因此先前純買進資料沒有暴露此錯誤。

11/20 published 帳本的該筆成交：

| 項目 | 金額（元） |
| --- | ---: |
| 買進手續費 | 5.123392018239581 |
| 賣出手續費 | 2.756644733594434 |
| 賣稅 | 5.803462597040914 |
| 已保存總成本 | 13.68349934887493 |

用相鄰成交的持股差額乘以本次成交價，再套用原費率，獨立重算與原總成本的差異小於 `1e-12` 元。11/20 四系統狀態為 complete，444／555／555 V2／V2.11 均已保存成功；此次故障不表示 11/20 的研究與日誌遺失。

先前測試只在更新前執行，當次更新後的狀態由 bot 以 `[skip ci]` 保存，因此新增賣出成交直到下一次執行才碰到錯誤假設。先前健康檢查驗證雜湊與帳本完整性，沒有實際載入 V2 展示成本契約。

## 修正

- 展示層以原協議 `Sell_Tax × BROKER_FEE_RATE ÷ SELL_TAX_RATE` 重建省略的 `Sell_Fee`，來源明標為推算；不使用 `Cost` 減其他欄位作自我驗證。
- 三項成本相加仍必須與原 `Cost` 一致。另逐日核對成交日期與 NAV 的 `Rebalance_Cost`，不能只靠總和相同掩蓋錯置日期。
- 成本表補上賣出手續費與重建依據；原 `Buy_Fee` 明標買進手續費。
- core／dashboard 健康檢查皆實際載入 V2 保存展示，檢查成本語意；只讀，不引入訓練／下載依賴。
- 每日更新後、發布前再次健康檢查；失敗時保留 artifacts，阻止錯誤狀態寫回 main，維持明確失敗通知。來源等待與合法部分結果仍保留原有處理。
- 實際持倉與目標權重在再平衡日可以相同，測試改為核對持股、成交價與 NAV，移除「兩者永遠不同」的日期依賴假設。

凍結推論程式、權重、模型卡、已發布訊號及原始保存帳本均不修改。這項修復不改交易邏輯或研究績效，不把通過測試解讀為第三方來源或 GitHub 排程永不失效。
