# 444／555 每日新聞與日誌恢復

日期：2026-11-17（臺北）。

## 停止原因

GitHub Actions仍有排程紀錄，但部分工作延遲至臺北翌日早晨才啟動。舊流程要求「最近已完成交易日＝實際執行日」，不相等就以`today_has_no_completed_session`跳過，回傳成功碼0，既不抓新聞也不建立reports日誌。

例如2026-11-17 07:01:53啟動的工作，資料截止交易日為11/16。舊流程只保存空的daily_summary；reports最新實際研究結果仍停在11/10。綠色Actions不能單獨證明模型、新聞或日誌已更新。

## 恢復後的日期規則

- 每次針對最近已完成的交易日處理，`as_of_date`／`output_day`是資料日，`run_date`與生成時間保留真正的執行日期時間。
- 延遲工作可更新新聞、444、555與研究日誌；日誌明確標記延後執行。若原預定進場已過，預測僅供研究，不當作可成交新訊號或前瞻命中。
- 同一資料日的成功輸出可重用；當天稍後有新完成交易日，使用另一個資料日目錄，避免早晨與當晚結果互相覆蓋。
- 延遲的V2.11只維護原已保存訊號之成交與成熟標籤，不補寫缺少的過去訊號。444／555完成與四系統全部完成分開報告。

## reports內容

- `reports/daily/<資料日>/`：444／555有效輸出、共同核心比較、新聞覆蓋摘要及狀態。即使一個模型等待，另一個成功模型仍保留獨立日誌。
- `reports/journals/444.md`、`555.md`：保存研究日誌與延後生成／進場過期註記。
- `reports/attempts/<實際執行日>/`：每次實際嘗試的不可覆寫JSON與彙整索引，包含跳過、等待、失敗與完成；新聞只記錄來源覆蓋等metadata，不公開新聞全文。
- `reports/latest/`：最新有效資料狀態。空的跳過工作、較舊資料日或失敗重試不能抹掉已發布的成功結果；其失敗仍在attempts記錄。

11/11、11/12、11/13、11/16等缺少原始當時訊號的期間，不能以現在重新訓練的結果補造為當時已發布的前瞻建議。新聞現時取得也不追溯證明歷史上已可使用。

## 驗證範圍

回歸涵蓋延遲資料日與實際執行日分離、444／555完成但追蹤器延後、進場過期標記、獨立模型日誌、跳過與較舊工作不倒退latest、失敗嘗試保留紀錄、相同嘗試冪等及attempt不可覆寫。

測試通過不代替線上新聞服務與GitHub排程的實際恢復驗收；實際完成資料日以本次`reports/latest/summary.md`及Actions紀錄為準。
